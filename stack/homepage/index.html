Farfield OS

An opinionated home-server bootstrap for Arch Linux. One script, one small computer, managed over SSH.

What this is

This is the operating layer of my home server — the machine that runs everything else at farfield.systems. One setup script takes a fresh Arch install and turns it into a server I never plug a keyboard into: a hardened shell, every language runtime I use, and an ingress stack that decides, deliberately, what the outside world can see.

Most days I don't administer it at all. Claude Code lives on the box with a map of the system, so managing the server is usually a conversation over SSH. When something needs a human, the shell is sharp and the dashboard is one command away.

Nothing here is exotic. It's ordinary tools, chosen once, wired together so I can stop thinking about them.

What's inside
Ingress
Tailscale for private access, Caddy for HTTPS and routing, a Cloudflare Tunnel for the few things that are deliberately public. No open ports on the router. Adding a site is one command: add-site, add-public-site, or add-preview-site.
Shell
Zsh with the Spaceship prompt, tmux by default, and the small sharp tools — ripgrep, fzf, eza, zoxide, bat. SSH in and it already feels lived-in.
Dashboard
If a display is attached, the box becomes a status board: six live panels — CPU, memory, network, disk, containers, operations — with touch. Headless, ff-dashboard draws the same board in tmux over SSH.
Runtimes
Node, Python (uv), Ruby, Rust, Go, Java, Docker, PostgreSQL, Valkey. Whatever the next project needs is already there.
Snapshots
Btrfs and Snapper photograph the system before and after every package transaction. A bad update is a reboot into yesterday, not an evening of repair.
Security
UFW, Fail2ban, hardened SSH. The public surface is opt-in, one hostname at a time.
Agent
Claude Code installed on the host with system context in ~/CLAUDE.md. The box is built to be worked on by an agent as much as by me.
Run it

You can run this. It's MIT, and the script doesn't know it's mine.

But be clear about what you're getting: every default is a decision I made for my own house. The prompt, the keybindings, what gets installed, what stays off — none of it will ask for your opinion. There is no configuration wizard, and there won't be one. If your decisions differ, fork it and make them yours. That's the intended path, not a workaround.

You'll need a machine with a fresh Arch Linux install, a non-root user with sudo, and SSH access. Public sites additionally want a domain on Cloudflare; private access wants a free Tailscale account.

git clone https://github.com/iammatthias/farfield-os.git
cd farfield-os
sudo ./scripts/setup.sh
sudo reboot
# after reboot, ff-bootstrap walks the one-time
# steps: tailscale auth, agent login. then: tmux

There's an uninstall script, and it leaves backups. But the honest advice is to read setup.sh before you run it — it's a personal bootstrap, not a product, and reading it is the fastest way to know whether you want it.
